# Experimental Niri width memory

This is an opt-in prototype, not a supported background service. Run `python3 features/niri_width.py` inside a Niri session; Ctrl+C stops it. It does not start automatically. It keeps one width per Niri app ID in `$XDG_STATE_HOME/vylmods-niri-dms/widths.json` (default `~/.local/state/vylmods-niri-dms/widths.json`) and restores it on newly opened tiled windows. Existing windows are not resized when the tool starts. Delete the state file to forget widths. It never changes window height or Niri configuration.

Niri 26.04 does not identify the cause of a width change or expose fullscreen state in its window IPC. The prototype skips windows that cover at least 90% of both display dimensions as a conservative fullscreen heuristic; this can also skip wide regular windows and is not a guarantee. It can still save layout-driven width changes and can affect other windows in the same column. Output sizes are captured at startup; restart the prototype after changing displays or scaling. It does not cover floating windows, apps without an app ID, multiple distinct widths for one app, or changes while it is stopped. There may be a visible resize on opening. It is not yet validated in a real Niri session; do not configure automatic startup until these limitations are addressed and it is tested on the target desktop.
